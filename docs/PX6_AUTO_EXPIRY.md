# PX6 到期前自动切换

将已有代理导入目标代理组后，系统保存 PX6 的 `unixtime_end` 到期时间。
在 PX6 网站续费或购买节点后，需要在面板重新选择目标组、填写 Key 并“导入目标代理组”，更新本地代理池；Key 不保存，没有定时访问供应商 API，也不会自动购买或续费。

默认合并导入会更新原节点的到期时间并保留账号绑定。不要为日常刷新勾选“替换该组已有节点”：替换会重建节点并触发账号重新绑定。

请求、授权刷新等操作解析账号代理时会检查到期时间：

- 距离到期超过 24 小时：保留原绑定。
- 距离到期不足或等于 24 小时：尝试绑定同组中到期时间超过 24 小时的可用节点。独占组只使用未被其他账号占用的备用节点；同一批到期或到期时间未知的节点不作为提前切换目标。
- 没有合适备用节点：保留当前尚未到期的节点；面板显示即将到期数量及缺少备用 IP 的账号数量。
- 已过期：不再使用该节点，尝试分配其他有效节点。没有有效节点时请求不能使用该组代理，不会隐式回退直连。

切换是请求前的按需操作，空闲账号不会被定时任务主动更换 IP。绑定变动在 SQLite 事务内完成，保留独占性，并清除旧 IP 的健康与地区资格缓存。

旧版数据库升级时增加可空 `proxy_group_nodes.expires_at` 列；已有节点保持原状，需要重新从 PX6 导入一次以补齐到期时间。没有 `unixtime_end` 的节点仍可照常使用，但无法自动提前切换；不猜测无时区 `date_end` 字符串的时区。

供应商字段依据：[PX6 官方 API 文档](https://proxy6.net/developers)。

回滚代码时可以保留新增的可空列，旧代码会忽略它；回滚版本将不再根据到期时间避开节点。无需删除或恢复凭证、账单及调用记录。
