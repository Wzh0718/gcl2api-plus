# 请求内容与特征监控

调用监控的账号、API Key 账号明细、实时记录优先展示凭证对应的邮箱；未获取邮箱时回退凭证文件名。脱敏开关同时控制邮箱显示及请求原文弹窗。

“实时”列表展示请求 SHA-256 指纹、消息数、工具数，以及请求详情入口。关闭脱敏后可查看客户端原始请求与网关上游请求的 system、messages、tools、生成参数，每部分附带 SHA-256 和 UTF-8 JSON 字节数。JSON 对象键排序后计算指纹，数组顺序及文本空白保留。

客户端采集支持 OpenAI Chat、Responses、Anthropic Messages、Gemini JSON 请求格式。上游内容取自 Antigravity 的最终请求体，包含转换/补充后的内容；重试只保留最终调用监控记录关联的请求体，不逐次保存重试历史。multipart 图片上传没有客户端 JSON 快照，但上游内容仍可保存。

原文保存在 SQLite `call_records.request_details`，摘要保存在 `request_features`。列表和内存缓冲区仅保留摘要；原文通过面板鉴权的 `GET /call-monitor/content?request_id=…` 按需加载，响应禁止缓存。正文与调用记录共用现有保留期及清理逻辑；历史记录无法补回原文。客户端入口不采集请求头或 URL 中的密钥，正文中的业务数据按原文保存。

数据库启动时自动补列，无需手工迁移。仅已进入现有计费/调用监控记录流程的请求会保存内容；鉴权或参数校验阶段拒绝的请求不产生此类记录。未接入计费监控的其他通道不因此新增调用记录。


“实时”列表主列优先显示上游耗时，鼠标悬停查看：

- 上游耗时：该条记录最后一次上游推理尝试发起至收到最后一段响应数据，包含连接建立；原生传输包含本机 helper 一跳。不会被 OAuth、凭证探测覆盖。
- 下游发送耗时：各次 ASGI 正文 `send` 调用耗时之和，不包含等待上游首段、后续数据或业务处理的时间。表示应用向网络层写出，无法证明远端客户端实际收完，也不包含反向代理缓冲。
- 辅助项：上游首字节等待、客户端响应等待（请求进入应用至开始发送非空正文）、请求总耗时（请求进入应用至最后一次正文发送完成）。总耗时包含等待，不等于下游发送耗时。

流式收发可能重叠，这些数值不能直接相加减；不能用总耗时减上游耗时推算下游发送耗时。SSE 首段可能是协议事件，不等于首个文本 token。断连时不虚构请求完成时间。

主列在新上游耗时未采集时回退原网关处理耗时，并在悬浮中注明。历史数据不推算新指标；未接入的传输、尚未采集的阶段显示“未采集”。仅进入现有调用监控的请求保存这些字段，不额外生成调用记录。

计时独立于正文采集开关。每个在飞请求仅有固定字段的计时对象，不保存正文、逐块时间线或重试历史，不增加后台任务、全局请求映射或无界队列。请求完成后更新现有 SQLite 记录和固定长度内存缓冲；数据随原记录按保留期删除。


慢请求诊断额外保留固定数量的阶段时间点（请求体接收完成、鉴权起止、API 进入、上游发起/最后数据、计费开始、监控写入起止），以及 stream、消息/工具数量、数值生成参数和输出格式类型。它们独立于正文采集开关，不包含正文、工具定义、URL 或密钥；不保留逐块或逐次重试历史，未知阶段名称不进入缓存。数据仍复用固定长度缓冲和原保留期。
