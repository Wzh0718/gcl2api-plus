# 客户端 System 侧载选项

在桌面版或手机版控制面板的「客户端提示词」中配置，保存后生效。仅作用于 Antigravity 通道。未配置混淆方案时默认关闭（off），需要时再选智能保护。AGY 基础提示注入默认开启且只注入官方基线；System 转 User 默认关闭，两者各自独立配置。

## 混淆方案（三选一）

| 方案 | 行为 |
| --- | --- |
| 关闭（off，默认） | 不混淆 |
| 全文 Leet（full） | 替换普通文本中的英文元音，附加明文解码说明并保留显式字面值和结构化输出约束 |
| 智能保护 Leet（protected） | 扫描整段客户端 System，转换普通说明，原样保留识别到的格式和字面值 |

已保存的 `off`、`full` 和 `protected` 继续生效。仅有旧布尔开关时，`true` 对应智能保护，`false` 对应关闭。控制面板同时保存新方案和旧布尔键。

### 字面值与解码说明

两种模式在转换提示词后附加元音映射 `a/e/i/o/u → 4/3/1/0/v`，大写对应 `4/3/1/0/V`。同一个字符可能有多个来源，模型结合上下文理解普通说明，逐字使用保留的内容。

- 两种模式都保留 `Return only…`、`Reply with exactly…` 等显式输出约束，以及行内代码、引号内容、JSON 对象和数组。`FINAL_JSON_START`、`FINAL_JSON_END` 一类大写下划线分隔标记即使没有加引号也会原样保留。
- 两种模式都根据实际工具定义和输出 Schema 保留提示词中的名称、字段和字符串枚举值，也保护已配置的停止词。智能保护模式将这些片段原样送出，不添加边界标签。全文 Leet 的普通文本模式可添加 `<gcli_literal>` 边界。输出约束语句以明文指令保留。
- 两种模式都支持在同一段系统提示词中用成对的 `<literal>...</literal>` 标记多行字面值或输出模板，保留块内的大小写、空白和换行。

### 结构化输出的自动保护

请求带有 JSON MIME 类型或响应 Schema 时，网关透传已有响应配置。请求只在提示词里约定输出时，网关从系统提示词和最近一轮用户消息识别明显的输出约定，包括中英文输出格式或 Schema 声明、JSON 等格式指令，以及成对的 JSON 起止标记。

识别到结构化输出后，网关跳过提示词融合。智能保护遍历所有客户端 System 文本，转换各处可识别的普通说明，按格式保留输出规则和字面值。提示词内的结构、客户端 Schema 和服务端 Schema 都可用于保护。用户沿用原 Key 和提示词即可，无需额外提供 Schema。

有 AGY 基础提示时，结构化请求将该宿主提示保留在 `systemInstruction.parts[0]`，并在 `parts[1]` 加入明文的输出优先级声明。该声明要求最终回复以生效的 Schema 或明确输出约定为准。文件链接、Markdown 格式和追问按输出约定处理。要求只返回 JSON 时，送给模型的指示明确要求裸 JSON。

网关保留提示词里的 Schema 和示例，由模型按原约定输出。需要服务端强制验收字段类型或补回固定分隔符时，可使用下方的流程绑定。

| 类别 | 智能保护的处理 |
| --- | --- |
| 结构与代码 | 保留成对括号内的字典和数组、引号内容、代码块和工具或环境章节。未闭合的代码块保留至文本末尾。 |
| 数字 | 保留小数、科学计数法、十六进制等进位制及带常见单位的数值。 |
| 路径和模板 | 保留绝对和相对文件路径、URL、文件名、模板变量、XML 标签、命令长选项、环境变量和常见标识符。 |

缺少输出约定时，网关按以上规则保护技术字面值。未声明的普通单词仍可能被当作说明文字转换。

### 服务端维护的固定流程

将管理员维护的 JSON 文件挂载进容器，设置 `ANTIGRAVITY_WORKFLOW_CONTRACTS_FILE` 为容器内路径。更新该文件后重启服务以加载新版本。`bindings` 按面板中的专用托管 API Key ID 选择流程版本。同一个 Key 只绑定一个流程版本，通用环境密钥留给通用调用。用户沿用原有协议、提示词和专用密钥即可。

```json
{
  "bindings": {"<托管 API Key ID>": "example-v1"},
  "contracts": {
    "example-v1": {
      "response_schema": {
        "type": "object",
        "required": ["results"],
        "properties": {"results": {"type": "array", "items": {"type": "string"}}}
      },
      "legacy_markers": ["FINAL_JSON_START", "FINAL_JSON_END"]
    }
  }
}
```

`response_schema` 是该流程用于请求和验收的 JSON Schema。智能保护使用相同的格式识别规则。`legacy_markers` 可省略，只有旧业务解析器需要起止行时才配置。

网关将服务端 Schema 用于已绑定流程的上游请求，并校验完整的模型 JSON。校验通过后按需生成旧起止标记。格式、字段或类型错误返回 HTTP 502，错误码 `invalid_workflow_output`。已绑定流程的流式响应完成校验后再返回，缓冲上限沿用现有非流式收集配置。请求证据中的生产提示词和实际 Schema 应经授权获取，以上字段仅供演示配置格式。

法规检索的 [regulation-search-v1](../src/prompts/workflow-contracts/regulation-search-v1.json) 按实际提示词约定维护 `embedding_query`、`rerank_query`、`policy_axes`。该流程启用 `legacy_markdown_prefix`，网关先校验结构化结果，再输出人工审阅 Markdown 和带起止标记的最终 JSON。仓库文件的绑定为空，管理员按部署环境填入该流程的专用 Key ID 后生效。

### 客户端识别

识别发生在敏感词替换前，结合身份声明和另一项结构信号，避免仅因正文提及客户端名称就命中。支持 Codex、Claude Code、DSH、Pi 的启发式结构规则，未命中则使用通用保护。识别结果不改变请求权限或提示词优先级。

DSH、Pi 等规则当前基于显式身份/结构样例，不能声称兼容这些客户端的所有真实版本。解析后的客户端文本仍经过现有敏感词过滤，智能保护只保证所识别片段不被 **Leet** 转换，不撤销敏感词规则已做的修改。

### 预览

预览默认折叠，处理后文本与附加解码说明分开展示。点击生成后发送到本服务试算，复用相同编码函数，不保存内容、不调用模型。仅处理输入文本，不叠加敏感词规则、请求工具定义、输出 Schema、角色转换或提示词融合。输出通过 textContent 显示。

## 客户端 System 转 User（独立开关）

将协议转换后的客户端系统提示放入会话开头的 user 消息，附加“先阅读并理解提示词，再处理后续任务，无需额外回复确认”的引导。空提示词不添加引导。是否遵守仍由模型决定，指导保持 user 优先级。

与任一混淆方案同时启用时，解码说明和编码后的客户端提示一起放入该 user 消息。启用任一混淆方案或 System 转 User 时，AGY 转换入口先保留 system，避免兼容模式提前将其混入普通用户任务。原始 system 消息可能已被协议转换器合并；后续非连续 system/developer 消息仍遵循现有协议转换规则。

## 处理顺序与组合

原始客户端 system → 识别客户端 → 现有敏感词过滤 → 选定混淆方案 → 按需转为 user → 注入服务端基础提示/前置文本。普通用户对话、工具定义、调用和结果不参与混淆；服务端提示、引导和解码说明也不参与混淆。

提示词融合使用保留的客户端原文生成新的指导。开启智能保护时，融合后的指导也经过相同的格式保护和 Leet 处理。融合失败时沿用已处理的提示词。所有混淆方案均不使用插字或零宽字符，不保证减少 429 或避免后续 403。

## 配置

| 配置键 | 环境变量 | 默认值 |
| --- | --- | --- |
| `antigravity_system_obfuscation_mode` | `ANTIGRAVITY_SYSTEM_OBFUSCATION_MODE` | `protected` |
| `antigravity_system_vowel_obfuscation_enabled`（旧键） | `ANTIGRAVITY_SYSTEM_VOWEL_OBFUSCATION_ENABLED` | 未设置时使用新方案默认值 |
| `antigravity_system_as_user_enabled` | `ANTIGRAVITY_SYSTEM_AS_USER_ENABLED` | `false` |

配置按新环境变量、旧环境变量、已保存的新方案、已保存的旧布尔值和默认值的顺序读取。环境变量控制时界面锁定对应设置。无效的新方案环境变量按关闭处理，面板 API 拒绝无效方案。
