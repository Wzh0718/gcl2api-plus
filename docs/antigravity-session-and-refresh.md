# 会话与 OAuth 刷新修复（2026-11-16）

## 会话归属

- 无显式 `sessionId` 的请求不再按首条用户文本合并，每次建立独立 conversation/trajectory。完整 messages/contents 仍由请求传入；不删除聊天历史，但不再为无标识请求推断稳定的上游会话。
- 现有 `sessionId` 输入继续作为显式续聊标识。内部键按账号、调用方 API Key、模型和该标识隔离。共享同一 API Key 的调用者仍须保证会话标识不冲突。
- 发往上游的 `request.sessionId` 使用账号状态中的稳定标识，调用方值不直接透传。conversation/trajectory 与账号级标识是不同概念。
- 显式会话使用 `explicit:v2` 缓存命名空间。升级时建立新 trajectory，旧 Redis 键按原 TTL 过期。
- Redis 用 Lua 原子完成初始化、步数分配和 TTL 续期。并发首次连接等待同一次初始化，避免部分请求提前回退到内存。
- 内存路径返回状态副本，后续请求不会改动前一个请求的步数。Redis 不可用时回退到进程内缓存，不保证跨 worker 连续；恢复 Redis 后也可能切回另一轨迹。

## 统一已有账号的刷新入口

`CredentialManager.get_account_credentials(filename, mode)` 是面板及辅助功能的统一加载入口。业务选号仍调用同一管理器的 `_refresh_token`，最终共同进入 `_refresh_token_once`。

已迁移：额度查询、项目验证、凭证测试、邮箱获取和 Gemini CLI preview 配置。返回的 Credentials 带刷新委托，因此 userinfo、项目列表等嵌套 helper 再次调用 refresh/refresh_if_needed 时也返回该入口，不另建独立刷新链路。初次 OAuth 登录、未入库 RT 导入仍是新授权流程，不按不存在的数据库账号协调。

- 提前刷新窗口为 300 秒，与核验的官方 Linux agy 一致。有效期 3599 秒时约 54 分 59 秒后进入窗口，下一次使用触发。
- 同一管理器、同账号同模式并发刷新共享 task；失败也由该批等待者共享。失败后数据库共享冷却 5 秒，再允许后续请求重试，不新增无限重试。
- 调用者取消不会中断其他等待者或刷新后的保存；管理器关闭等待已启动 task 完成。
- 发起 OAuth 前重新读存储，复用另一请求已保存的新 token；缺失账号不发起刷新。
- 统一保存 access_token、token 别名、expiry、返回的新 refresh_token 和 oauth_client_key，保留其他凭证字段。
- 面板查询不再自行保存序列化快照，也不再用字典序列化差异推断“发生刷新”。

## 防止旧授权覆盖

每次普通凭证保存/重新导入、条件更新都会生成新的内部 `_credential_revision`。即使删除后用完全相同的凭证内容重建，版本也不同。该字段不是秘密、不发送给 OAuth 服务；客户端提供的旧版本会被普通保存覆盖。无该字段的旧记录可在首次条件更新时平滑升级，无需表结构迁移。

存储新增 `compare_and_swap_credential`：仅当记录仍存在、完整凭证快照仍等于期望值时，才更新凭证与相关状态。不使用 upsert，不回退为普通 store。

- SQLite：BEGIN IMMEDIATE 内检查快照，再更新并提交。
- PostgreSQL：单条带 filename 与 JSON 快照条件的 UPDATE。
- MongoDB：带 filename 与 credential_data 条件的 update_one，upsert=False；相关状态变化后同步可用池。

刷新期间如果另一请求保存了新授权，旧刷新结果被丢弃。若当前 token 有效，调用者可使用当前版本；否则此次操作失败，等待后续重试，不用旧结果覆盖。旧 invalid_grant 的诊断与禁用也在同一条件更新中，不能禁用已经重新授权的账号。账号已删除时不能被刷新回调重新创建。

项目验证更新 project_id、清除错误和解除禁用也使用同一条件更新。期间授权改变时返回 HTTP 409，避免旧项目结果携带旧 token 写回。

## 并发边界与发布

进程内 task 合并之外，统一刷新入口现在使用数据库租约。当前 StorageAdapter 固定选用 SQLite，租约实现覆盖此实际运行后端；保留的 PostgreSQL/MongoDB 尚未实现租约，不能直接切换后端并宣称具有相同保证。

- 启动时自动创建 `credential_refresh_leases`。互斥键为 `(mode, basename(filename))`，持有者使用每次尝试唯一的 UUID；不保存 token、提示词或其他秘密。租约跨授权版本仍互斥，旧版本结果另由 CAS 拦截。
- TTL 60 秒，每 15 秒续租，单次操作上限 45 秒，等待上限 90 秒。失去租约、续租报错、超时会取消本地刷新任务；协调失败不退回无锁刷新。OAuth 发出前再次续租确认归属。
- 等待者先检查凭证是否已更新，再争抢租约；退避轮询从约 100ms 增至约 1 秒并加入随机抖动。有有效租约时只读，不反复争夺 SQLite 写锁。拿锁后再次读凭证，有新结果直接复用。
- OAuth 网络请求在数据库事务之外执行。写入 token 或 OAuth 失败诊断时，在同一个 `BEGIN IMMEDIATE` 事务里检查租约持有者、有效期及凭证快照，防止旧持有者越权写回。
- 释放/续租都校验 owner，过期租约不能复活，旧进程不能删除新租约。成功后释放；失败后共享 5 秒冷却，避免排队的进程接连刷新失败账号。崩溃未释放时自动过期。

作用范围是**共享同一 SQLite 数据库文件**的已升级进程；不同数据库副本、独立官方客户端、同一授权重复导入为不同文件名不在此互斥范围。SQLite WAL 应使用支持本地文件锁的共享本机存储，不以多机网络文件挂载代替共享数据库服务。初次授权/RT 导入仍不适用已有账号锁。

这不能保证远端 OAuth“恰好一次”：服务端已经处理成功、本地未保存就崩溃，或进程长时间暂停导致租约过期，仍存在恢复后重复请求的窗口。租约丢失后取消本地任务不能撤回已经发出的远端请求；CAS 则会拒绝旧结果。

所有写凭证的服务实例须升级后才具备该保护；旧版本的普通无条件写入可以绕过新规则。外部脚本直接修改数据库也不受应用入口约束。当前工作区尚未部署。

## 验证

- 会话专项回归：无标识请求隔离、显式续聊、账号/调用方隔离、Redis 原子分配和初始化、内存快照、sessionId 不透传。
- 隔离 Redis 7 实测：两个客户端并发分配 200 次，步数唯一且覆盖 1–200；TTL、删除后初始化正常。测试容器已清理。
- 真实 SQLite 并发回归：两个写者仅一个提交；刷新与重新授权、删除、删除重建交错；旧 invalid_grant 不禁用新授权；当前 invalid_grant 原子记录与禁用；项目验证冲突；无版本旧记录升级；业务/额度/辅助入口共用刷新。
- PostgreSQL、MongoDB 已做条件更新接口契约测试，未在本轮启动这两种真实数据库进行集成测试。
- Python 编译、前端 JS 语法、diff 空白检查通过。前轮全量 pytest：1170 passed，6 条既有依赖弃用警告；本次租约验证结果见下文。

这些改动针对可复现的正确性问题，不证明 Google 扫码/SMS 验证或账号失效的根因已经解决。

### 数据库租约补充验证

- 4 个独立 Python 进程共享真实 SQLite 数据库，同时刷新同一账号：模拟 OAuth 仅调用 1 次，4 个进程均返回相同新 token。
- 真实子进程持有租约后直接退出：租约到期可接管。
- 覆盖过期后的续租拒绝、旧成功/失败写回拒绝、旧持有者释放不影响新租约、续租延长、失败共享冷却、账号/模式隔离。
- 覆盖数据库获取租约失败时不发送 OAuth、续租失败/操作超时取消任务、不写旧结果；5 个管理器共享一次失败尝试。
- 本轮全量测试：**1178 passed，6 条既有弃用警告，50.16 秒**。编译、JS 语法和 diff 空白检查通过。
- 测试使用模拟 OAuth，不对真实 Google 账号增加刷新请求。修改尚未提交或部署。
