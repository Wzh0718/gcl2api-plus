# 出口 IP 检测频率与证据边界

本次修复覆盖 `check_antigravity_account_health` 使用的 IP 回显探测（手动检测、批量检测、运行时健康检查和改绑检查共用）。不增加定时探测，不对每次 OAuth/生成请求额外探测。

- 相同回显 URL + 实际代理配置共用 30 分钟缓存；账号之间可复用。继承代理先解析配置，代理或回显 URL 改变后使用新缓存键。
- 同一 worker 同时最多一个 IP 回显请求，新请求启动间隔至少 2 秒。并发检查同一出口时，排队者复用结果，不重复探测。
- 非成功响应、超时、解析失败缓存 5 分钟；取消中的探测也保留冷却，避免再次立即请求。HTTP 429 单独按 30 秒缓存，冷却结束后同一条线路即可重新探测。
- 429/503 对回显服务主机整体冷却：默认 30 秒，尊重 `Retry-After` 秒数或 HTTP 日期但只采纳 1–60 秒区间。冷却上限刻意压到 60 秒——单次瞬时限流不应让整批导入和其他线路的探测在 5 分钟内全部短路（那会把“探测被限流”误报成“没有空闲出口 IP”）。
- 无强制绕过入口。成功缓存可能延迟最多 30 分钟发现供应商出口变化。这是采样周期，不是线路实时证明。
- 缓存有容量上限；状态为 worker 内存态，重启清空，多 worker 的限速额度各自计算。当前方案不是跨副本全局限流，部署多个副本时需另设共享限额或按副本降低配额。

每次实际探测产生 `[EGRESS_OBSERVATION]` 应用日志，含探测/路线摘要、HTTP 状态、采样时间、IP、国家或异常类型。缓存命中不伪造新的采样时间，也不重复输出采样日志。日志不含代理 URL、密码、账号 token 或回显响应全文；沿用应用日志的保留策略。

这是“该时刻经该代理访问回显服务所看到的出口”，不能当作 Google 实际看到的出口，更不能证明 TLS 握手。按域名分流或供应商动态路由时两者可能不同。

本次没有改变 Google 资格检查和消息测试的调用频率；这里只限制第三方 IP 回显请求。默认限制并不代表供应商承诺的额度，实际使用仍需与所配置服务的额度匹配。未对生产回显服务发送测试请求。
