# 调用监控详情压缩维护

`credentials.db` 同时存放凭证、配置、账单和调用监控。文件大不代表凭证本身大。
调用详情 `call_records.request_details` 使用带版本标记的 zlib BLOB 无损压缩，
旧版 JSON TEXT 继续可读。列表、统计和计费字段不变，详情接口按需自动解压。

临时关闭正文采集：配置 `call_content_capture_enabled=false`，或在没有该数据库
配置时设置环境变量 `CALL_CONTENT_CAPTURE_ENABLED=false`（数据库配置优先）。
关闭后不再复制、解析和保存客户端/上游正文快照及内容指纹；调用记录、Token、
状态和计费照常保存，转发给上游的实际请求不变。改回 `true` 可重新启用。

历史数据不在启动时自动转换，避免长时间阻塞服务或在磁盘满时产生大量 WAL。
维护流程：

1. 部署支持压缩读写的版本；核对详情接口能够读取新旧格式。
2. 暂停所有数据库写入方，制作并验证一致的数据库备份。
   WAL 模式下不能在服务写入时只复制 `.db` 文件。
3. 使用对应版本中的独立标准库工具转换历史详情：

   ```bash
   python3 src/storage/call_record_content.py /path/to/credentials.db --vacuum
   ```

   工具按批次提交，仅更新旧版 TEXT；对每条压缩结果回读解压，核对原始 UTF-8
   字节完全相等，失败时回滚当前批次。重复执行会跳过已压缩记录，不删除记录。
   输出仅包含条数和字节数。`--vacuum` 会在完整性检查后回收空页；空间不足则
   保留已经转换的数据并报错，可腾出空间后再次执行。
4. 核对完整性检查、凭证和账单记录数、历史详情及新请求详情；恢复服务。

历史转换完成后，回滚应用也必须保留压缩读取支持。旧版本直接对 BLOB 调用
`json.loads` 无法读取详情；需要回滚时使用兼容版本或恢复一致备份。
部署备份中的数据库也会占用空间，可在确认没有进程使用后另行无损压缩归档。
