# 智能保护 Leet 实现与生产账号测试

最终验证时间：2026-11-17 15:45:45–15:46:30（Asia/Singapore）。

## 实现

混淆方案改为关闭 / 全文 Leet / 智能保护 Leet，旧布尔配置保持兼容，System 转 User 继续独立配置。智能方案识别客户端身份与结构，保留代码、引用、有效 JSON、路径、URL、标识符、工具名/参数/枚举及明确的输出约束，混淆剩余文本后附加解码说明。识别在敏感词过滤前执行。

输出约束保留为原文指令，不包成数据标签；没有精确数据片段时不引入标签说明。数据片段边界避免与源文本冲突，解码说明明确要求不在回答中添加边界标签。

## 生产测试方式

使用一个此前成功账号（引用 `4f9395909cda`）、其已有代理及 `gemini-2.5-flash-lite`。在本地用当前实际 normalizer 生成合成请求，在生产容器内复用当前生产请求包装与传输方法发送。每次 temperature=0，maxOutputTokens=512，请求间隔 2 秒，出现 HTTP 失败即停止，不重试或轮换账号。源文件 SHA-256 随报告保存并已核对。

没有部署代码或修改生产全局开关；凭证和代理认证信息留在生产容器进程内。工具只记录调用，不执行。跳过提示词融合、基础系统提示及自定义前缀，隔离待测转换。直接上游请求消耗正常额度，未走对外 API 的计费/调用监控写入；usage 见 summary.json。

## 结论与限制

本组证据表明智能保护能修复全文 Leet 在 JSON、工具参数和路径上的明确破坏；早期测试也证明，额外解码提示本身并不能保证模型遵从。最终小样本通过不是通用质量保证，自动识别仍可能遗漏未标记的精确词，建议显式使用反引号或代码块。默认仍关闭。

单账号、单模型、合成短提示；没有测试真实客户端全流程、多轮长任务或其他模型。原文对照也全部成功，因此不能证明能减少 429，也没有验证延迟 403 或留存审计结果。

- prepare_requests.py：通过当前本地 normalizer 重新生成请求的脚本。
- initial/、decoder-only/、tagged-contract/、plain-contract/：中间轮次的输入与输出。
